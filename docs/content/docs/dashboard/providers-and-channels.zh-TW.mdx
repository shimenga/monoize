Provider 排序儲存後立即生效，無須等待快取到期。既有 Channel 綁定與親和性規則仍然有效。

## 概念

- **Provider（服務供應商）** 屬於一個 Group。它定義路由順序、預設價格、健康策略和有序的變換鏈。
- **Channel（通道）** 是 Provider 唯一的上游端點。它保存上游類型、基底 URL、憑證、模型對應和逾時。

請求先選擇 Provider，再在其中選擇 Channel。選擇規則參見[路由與可靠性](/zh-TW/docs/routing)。

## 建立 Provider

1. 在側邊欄開啟**服務供應商**。
2. 點擊建立按鈕並輸入名稱。
3. 選擇一個 Group，並設定內嵌 Channel。
4. 確認 Provider 和 Channel 名稱可以顯示在公開頁面中。
5. 預設值不合適時，設定 `channel_max_retries` 和 `channel_retry_interval_ms`。
6. 除非有明確理由，保持 `circuit_breaker_enabled` 開啟。

## 設定 Channel

1. 開啟 Provider 並選擇 **Channel**。
2. 選擇上游類型：`responses`、`chat_completion`、`messages`、`gemini`、`openai_image` 或 `replicate`。
3. 填寫上游基底 URL 和 API 金鑰。
4. 可選：設定 `proxy_url`，覆寫程序層級上游代理。

之後編輯 Channel 時，API 金鑰留空則保持原有金鑰不變。

## 工作階段快取標頭

在 Channel 上設定**自動工作階段親和**，即可在每個轉送請求上送出穩定的工作階段識別碼。

該設定為 `null` 時，Monoize 對以下基底 URL 自動開啟：

- Cloudflare Workers AI：`https://api.cloudflare.com/client/v4/accounts/{account_id}/ai`（可選 `/v1`）
- OpenCode Zen 或 OpenCode Go：`https://opencode.ai/zen` 及其子路徑

開啟後，Monoize 用同一值送出這兩個標頭：

- `x-session-affinity`
- `x-opencode-session`

取值順序：Channel 自訂標頭中的上述任一名稱、用戶端標頭（`session_id`、`session-id`、`x-session-id`、`x-opencode-session` 或 `x-session-affinity`）、請求主體中的工作階段識別碼、`prompt_cache_key`，最後是工作階段開頭的雜湊。

OpenCode Go 用 `x-opencode-session` 將工作階段綁定到提示快取。缺少該標頭的請求可能失敗。

對 OpenCode Zen 或 OpenCode Go 的存活探測：當 Channel 自訂標頭未設定這兩個名稱時，送出字面值 `mono-probe`。

## 測試 Channel

開啟 Channel，執行順序測試或並行測試。

測試會送出一次短串流補全，輸出上限為 16 個 token。僅 HTTP 2xx 不夠。串流必須到達協定終結事件。

對 Responses Channel，`response.completed` 算通過。沒有 error 物件的 `response.incomplete` 也算通過。推理模型可能打滿 16 token 上限並回傳 `incomplete`。該結果仍表示 Channel 可達。

## 對應模型

內嵌 Channel 列出它服務的邏輯模型。模型對應包含：

- `redirect`：真實的上游模型名稱。留空則按邏輯名稱原樣送出。
- 價格 Profile 模式：繼承 Provider 預設值、覆寫預設值或設為未定價。
- 可選倍率覆寫。未設定時繼承 Provider 倍率。

只有當 Channel 已啟用且模型對應具有完整價格時，該模型才會路由到這個 Provider。

出現定價警告時仍可儲存 Provider。檢查每條警告中的邏輯模型和缺失 usage class。傳送流量前新增缺失費率。

## Provider 變換

Provider 可以持有一組有序的變換規則。它們在 Provider 選定之後、上游編碼之前，作用於該 Provider 服務的每個請求。參見[變換](/zh-TW/docs/transforms)。

## 批發 Provider

`agent`（代理）分組服務代理帳戶，不持有普通 Provider。

1. 先建立一個 `agent` 類別的 Group：可在**服務提供者**頁把**目錄範圍**切換到 `agent` 後建立，也可在沒有代理分組時直接在批發對話框內建立。
2. 點擊**新增批發 Provider**。
3. 選擇一個屬於 `standard`、`enterprise` 或 `private` 類別的現有 Provider 作為來源。
4. 系統一次性複製來源 Channel 設定和模型映射。複製後彼此獨立，來源的變更不會同步。
5. 每個模型的倍率預設等於來源倍率。儲存前可修改任意倍率，之後也可用普通 Provider 編輯器修改。
6. 批發 Provider 複用來源的 Billing Profile，用自己的倍率決定批發價格。

只有代理帳戶能看到代理分組、在其中建立 API key 並使用其倍率。代理帳戶的模型市場與其他類別遵循同一套規則。

## 群組

每個 Provider 只屬於一個 Group。API 金鑰只會路由到其允許 Group 中的 Provider。使用 Group 區分使用者等級或環境。

建立或重新命名 Group 時確認公開顯示。公開模型廣場和狀態頁會顯示已確認的 Group、Provider 和 Channel 名稱。
